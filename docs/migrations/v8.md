All three changes come from one update of the MDX rule in
`defaults/webpack.config.js`:

```diff
+import rehypeMdxCodeProps from "rehype-mdx-code-props"
 // …
         {
           test: /\.mdx?$/,
           // …
-          use: [swcLoader, { loader: require.resolve("@mdx-js/loader") }],
+          use: [
+            swcLoader,
+            {
+              loader: require.resolve("@mdx-js/loader"),
+              options: {
+                // The meta of a code block, eg. `file="src/app.tsx"`, becomes
+                // props of the `code` component. `tagName: "code"` replaces
+                // the default of the plugin, `pre`
+                rehypePlugins: [[rehypeMdxCodeProps, { tagName: "code" }]],
+              },
+            },
+          ],
         },
```

## A code block meta must be JSX attributes

The meta is the text after the language of a code block. Write it as JSX
attributes: a string in quotes, any other value in `{}`, a flag alone.

````md
<!-- Before -->

```tsx file=src/app.tsx {1,3}
const a = 1
```

<!-- After -->

```tsx file="src/app.tsx" lines={[1, 3]}
const a = 1
```
````

**If unchanged**:

- The build of a page with `file=src/app.tsx` fails with
  `Unexpected character … before attribute value`
- The build of a page with `{1,3}` fails with
  `Could not parse expression with acorn`

**Reason**:

- `rehype-mdx-code-props` reads the meta as JSX attributes. A value keeps its
  type: `lines={3}` is a number, `isOff={false}` is `false` ([decision 03])

## The `code` component receives the meta

VBlocks now passes a valid meta, eg. `title="Example"`, to the `code` component
as props.

````md
```tsx title="Example"
const a = 1
```
````

```tsx
// Before
const Code = (props: ComponentProps<"code">) => <code {...props} />

// After
const Code = ({ title, ...props }: ComponentProps<"code">) => (
  <code {...props} />
)
```

**If unchanged**:

- A `code` component that spreads its props onto `<code>` writes each meta
  attribute into the HTML, eg. `<code title="Example">`
- The browser shows a `title` attribute as a tooltip
- Without a `code` entry in `components`, the meta becomes attributes of the
  plain `<code>` element

**Reason**:

- A custom `code` component can read the meta, eg. a file name or the
  highlighted lines, to change how it renders a code block ([decision 03])

## An ejected `webpack.config.js` imports `rehype-mdx-code-props`

An ejected config loads its plugins from the project folder, not from VBlocks.
Install the package there, when you eject `webpack` again or copy the MDX rule:

```sh
# Before
npx vblocks eject webpack > webpack.config.js

# After
npx vblocks eject webpack > webpack.config.js
npm install --save-dev rehype-mdx-code-props
```

An ejected config from v7 keeps working. It lacks the plugin, so the `code`
component receives no meta.

**If unchanged**:

- Node reports
  `ERR_MODULE_NOT_FOUND: Cannot find package 'rehype-mdx-code-props'` when
  `serve` or `build` loads the config

**Reason**:

- An ejected config stays one file, so its plugins come from the project
  ([decision 03])
