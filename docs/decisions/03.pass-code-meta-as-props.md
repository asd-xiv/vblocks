# 03. Pass the meta of a code block as props

**Date**: 2026-11-19

**Independent facts**:

- A fenced code block has a language and a meta, the rest of its opening line,
  eg. `file="src/app.tsx"` in ` ```tsx file="src/app.tsx" `
- MDX keeps the meta out of the props of the `code` element, so a `code`
  component of `components` never receives it
- MDX turns a number property of a plain element into a string. It removes a
  `false` property. A JSX element keeps both
- `rehype-mdx-code-props`:
  - reads the meta as JSX attributes: a string in quotes, any other value in
    `{}`, a flag alone
  - replaces the `code` element with a JSX element, which keeps the type of each
    value
- `vblocks eject webpack` prints one file
- An ejected config loads its plugins from the project folder

**Problem**:

- A page cannot tell its `code` component the file, the highlighted lines or any
  other fact a code block states

**Solution**:

- `defaults/webpack.config.js` runs `rehype-mdx-code-props` on `code`, so the
  `code` component receives the meta as props
- The meta is JSX attributes: `file="src/app.tsx" lines={3} showLines`

**Rejected**:

- A rehype plugin of VBlocks, with its own meta syntax, eg.
  `file=src/app.tsx lines=3`. It needed about 125 lines of MDX internals to keep
  the types of the values, and VBlocks would maintain them

**Acknowledgments**:

- An ejected config needs `rehype-mdx-code-props` in the project folder
- `rehype-mdx-code-props` had its last release in June 2024. A later major
  version of MDX or unified may break it. VBlocks then needs to fork it or send
  a pull request
- A meta that is not JSX attributes fails the build
